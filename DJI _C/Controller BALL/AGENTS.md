# AI 对话前置约束文档

## 核心要求

1. **禁止臆想硬件信息**：对于任何不清楚、不确定的硬件连接、引脚分配、外设参数，必须返回询问用户，不允许自行假设或猜测。

    

2. 不要自动使用make检查编译错误，忽略build目录下的文件，这是编译自动生成的文件。

3. 忽略MDK_ARM下的文件

4. **每次执行对话前请阅读当前文档**

## 平衡杆已确认参数

1. 小球位置使用管道上的实际位置坐标，单位为厘米（cm）。

2. 本次开环动作顺序为：`0 cm` -> `+5 cm` -> `-5 cm`，最终停留在 `-5 cm`。

3. 电机正角度使小球向 `-5 cm` 方向移动，电机负角度使小球向 `+5 cm` 方向移动。

4. 电机 `0 rad` 对应平衡杆的机械平衡点。

5. 平衡杆允许的角度调控范围为 `-0.8 rad` 到 `+0.8 rad`。

6. TASK1控制平衡杆在+5到-5间不使用视觉，TASK2、TASK3需要使用视觉。

## 代码架构

1. BSP文件夹，存放底层BSP硬件驱动。inc存放.h文件，src存放.c文件。没有文件夹就自行创建

2. APP文件夹，存放应用层实现函数，包括pid算法、具体任务要求、ui实现。没有文件夹就自行创建

3. 使用stm32 cubemx生成代码，hal库编写代码，不要直接帮我写入cubemx可以生成的代码，需要我生成的代码请提示用户使用cubemx生成

## 代码规范

1. 只要写入代码就需要添加注释，不要等用户提醒。

2. **注释风格**：统一使用Doxygen标准（`@file`/`@brief`/`@param`/`@return`），只在接口声明和函数内部关键逻辑处标注，保持代码整洁，禁止逐行注释。

3. **变量命名**：简洁易读，不要使用冗长的英文全称，尽量减少三元运算符。在含义明确的上下文中优先使用简短命名。
   - 反例：`interval_ms` → 正例：`ms`
   - 反例：`motor_direction` → 正例：`motor_dir`
   - 原则：能一眼看懂即可，不追求英文完整拼写
